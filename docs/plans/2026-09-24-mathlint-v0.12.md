# mathlint v0.12 "Camera and handwriting" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Photograph printed or handwritten math, or write it on the screen, and get editable notebook lines — recognized on the device, offline, in about 5 MB.

**Architecture:** A training project (`training/`, PyTorch) generates license-clean data (formula sampler → layout engine → printed / handwritten / photographed renderers), trains a compact CNN encoder + Transformer decoder, and exports an int8 `recognizer.bin`. The browser runs it with a small hand-written JavaScript inference library in a Web Worker; the camera and the pad feed it images, and the result is written into the notebook with an animation.

**Tech Stack:** Python 3.12, PyTorch (CUDA 12.8+), Pillow, NumPy (training only); plain ES modules and `node --test` in the browser.

**Spec:** `docs/design/2026-09-24-camera-design.md`

## Global Constraints

- Training data: only commercially usable sources (generated, open fonts, ODbL, CC BY; EMNIST only if its terms allow). No MathWriting, CROHME, HME100K.
- Model at most 4 MB (int8); recognizer code at most 60 KB gzipped; a line in under 3 s on a mid-range phone.
- The recognizer is not precached at install; it is fetched on first use and then kept in the versioned cache.
- Nothing leaves the device; photos and strokes are not stored.
- The package's own `uv.lock` and dependencies are untouched: training has its own project.
- Every UI word in en, ro, ru, es; recognized math is spoken like typed math.
- Every commit: ruff, pytest, `node --test web/tests/*.test.mjs` pass; commits end with the Co-Authored-By line.

### Task 1: The training project and the formula sampler

**Files:** Create `training/pyproject.toml`, `training/README.md`, `training/mathrec/__init__.py`, `training/mathrec/vocab.py`, `training/mathrec/formulas.py`, `training/tests/test_formulas.py`; modify `.gitignore` (`training/data/`, `training/runs/`).

**Interfaces — Produces:**
- `vocab.TOKENS: list[str]`, `vocab.tokenize(latex: str) -> list[str]` (raises `ValueError` on a token outside the vocabulary), `vocab.encode(tokens) -> list[int]`, `vocab.decode(ids) -> str`; ids 0,1,2 = `<pad>`, `<s>`, `</s>`.
- `formulas.sample(rng: random.Random) -> str` — one LaTeX formula the editor can read; `formulas.corpus(n, seed) -> list[str]`.

- [ ] Tests: every sampled formula tokenizes; `decode(encode(tokenize(x))) == normalize(x)`; the corpus covers every kind (linear, quadratic, fractions, systems, inequalities, powers/roots, derivatives, integrals, limits, matrices); `mathlint`'s LaTeX reader (`mathlint.parse.latex.latex_to_plain` + `parse_expression`/`parse_equation`) reads at least 99% of them.
- [ ] Implement; commit `feat(training): a formula sampler and the recognizer's vocabulary`.

### Task 2: Layout engine and printed renderer

**Files:** Create `training/mathrec/layout.py`, `training/mathrec/render_printed.py`, `training/mathrec/fonts.py` (downloads pinned OFL fonts into `training/data/fonts`), tests.

**Interfaces — Produces:** `layout.parse(latex) -> Node`; `layout.place(node, size) -> list[Glyph]` with `Glyph(symbol: str, box: (x, y, w, h), baseline: float)`; `render_printed.render(latex, rng) -> PIL.Image` (grayscale, height 96 after resize).

- [ ] Tests: fraction numerator above the bar above the denominator; superscript raised and smaller; sqrt box covers its radicand; every glyph inside the image; output height 96.
- [ ] Commit `feat(training): lay out formulas and typeset them in open fonts`.

### Task 3: Handwritten symbols and the handwritten renderer

**Files:** Create `training/mathrec/symbols.py` (downloads Detexify strokes and HASYv2, pinned by hash, maps their labels to vocabulary tokens), `training/mathrec/render_hand.py`, tests; add attributions to `THIRD_PARTY_NOTICES.md`.

**Interfaces — Produces:** `symbols.bank() -> dict[str, list[Sample]]` (`Sample` = strokes or bitmap); `render_hand.render(latex, rng, strokes_only=False) -> PIL.Image`; `render_hand.strokes(latex, rng) -> list[list[(x, y)]]` for the pad.

- [ ] Tests: every vocabulary token that is a symbol has at least 20 samples (or a documented fallback to a jittered font glyph); rendering is deterministic for a seed.
- [ ] Commit `feat(training): handwritten formulas from real handwritten symbols`.

### Task 4: Photographed samples and the dataset

**Files:** Create `training/mathrec/photo.py` (paper, ruled lines, perspective, light, blur, JPEG), `training/mathrec/dataset.py` (a PyTorch `Dataset` generating on the fly, plus fixed held-out sets written to `training/data/eval/`), tests.

- [ ] Tests: augmentation keeps the formula readable (ink still inside the frame); fixed eval sets are identical across runs.
- [ ] Commit `feat(training): photographed samples and the training dataset`.

### Task 5: The model, training and evaluation

**Files:** Create `training/mathrec/model.py`, `training/train.py`, `training/evaluate.py`, `training/mathrec/beam.py`, tests.

**Interfaces — Produces:** `model.Recognizer(vocab_size)` with `encode(images) -> memory`, `decode(memory, tokens) -> logits`; `beam.search(model, image, width=4, valid=callable) -> list[(tokens, probs)]`; `evaluate.py` prints expression rates per set.

- [ ] Tests: forward shapes; parameter count ≤ 4.0 M; a tiny model overfits 16 samples in a few hundred steps.
- [ ] Train; record results in `training/README.md`; commit `feat(training): a compact image-to-LaTeX recognizer`.
