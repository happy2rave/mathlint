# mathlint v0.11 "App quality" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.11.0: translated steps and interface (ro, ru, es), history and favourites, an installable offline app, faster start-up with budgets, and screen-reader support for math.

**Architecture:** Python keeps writing English, but through `msg()`, which returns a `str` subclass that remembers its template; `web_api.handle` localizes the reply at the edge. The page gets its own small modules (`i18n.js`, `history.js`, `speech.js`, `sw.js`) and the build vendors every CDN file so a service worker can cache the whole app.

**Tech Stack:** Python 3.10+, SymPy, pytest, ruff; plain ES modules, MathLive, KaTeX, Pyodide; `node --test` for JavaScript units.

**Spec:** `docs/design/2026-09-23-app-quality-design.md`

## Global Constraints

- Languages: `en` (source), `ro`, `ru`, `es`. Anything untranslated falls back to English.
- English output of every existing command and test is unchanged.
- The page makes no third-party requests after the build (vendor everything).
- `localStorage` keys: `mathlint:lang`, `mathlint:history`, existing `mathlint:theme`, `mathlint:last-solution`; every access in `try/catch`.
- History: at most 200 unstarred entries; starred never dropped.
- Every commit: `uv run ruff check .` and `uv run pytest` pass; commit messages end with the Co-Authored-By line.

### Task 1: The message catalog core

**Files:**
- Create: `src/mathlint/i18n.py`, `src/mathlint/locales/{ro,ru,es}.json`, `scripts/extract_messages.py`
- Modify: `src/mathlint/web_api.py` (`handle`), `src/mathlint/cli.py` (`--lang`)
- Test: `tests/test_i18n.py`

**Interfaces — Produces:**
- `msg(template: str, **args) -> Message` — English rendering via `template.format_map(args)`.
- `class Message(str)` with `.template`, `.args`; `Message + str` and `str + Message` return a `Message` joining the parts.
- `join(separator: str, parts) -> Message`
- `LANGUAGES = ("en", "ro", "ru", "es")`
- `localize(value, lang: str)` — returns the same structure with every `Message` rendered in `lang`, and `\text{...}` words in strings rendered from the catalog's `latex` section.
- `render(value) -> str` — localize one string in the current language (`use_language(lang)` context manager sets it; CLI uses it).
- Catalog file shape: `{"messages": {"<English template>": "<translation>" | null}, "latex": {"or": "sau"}}`

- [ ] Step 1: failing tests — English identity (`msg("Add {n} to both sides", n="3") == "Add 3 to both sides"`), translation with a fake catalog, nested message args, concatenation keeps localizability, unknown template falls back to English, `handle("solve", '{"text": "x+1=3", "lang": "ro"}')` returns Romanian step text for a translated template.
- [ ] Step 2: run, see them fail.
- [ ] Step 3: implement `i18n.py`, `handle` reads `lang` from the payload (default `en`), CLI `--lang` on `solve`, `steps`, `check`.
- [ ] Step 4: `extract_messages.py` walks `src/mathlint` with `ast`, collects constant first arguments of `msg(...)` calls, and adds missing keys as `null` to every catalog while removing stale ones (`--check` exits 1 instead of writing).
- [ ] Step 5: catalog tests — every catalog has exactly the extracted templates, every non-null translation uses the same set of `{placeholders}`.
- [ ] Step 6: run tests, commit `feat(i18n): a message catalog for everything the solver says`.

### Tasks 2–6: Wrap and translate, one family per commit

For each family: replace user-facing f-strings with `msg(...)`, run `extract_messages.py`, fill in `ro`, `ru`, `es`, and run the whole suite (English unchanged).

- Task 2 `solve/` (every solver, `core.py` answer text, `KIND_LABELS`, `METHOD_LABELS`, intervals, sign charts, systems).
- Task 3 `calc/` (arithmetic, expand, factor, simplify, analyze, computation, api).
- Task 4 `steps/` (calculus, derivatives, integration methods, limits, odes, series, linalg, matrix, solution titles).
- Task 5 `check/`, `hints.py`, `report.py`, `document.py`, `errors.py`, parse errors reaching the page, `web_api` messages.
- Task 6 `explain.py` (every `Why`), `practice.py`, `graph.py` labels.

**Test (added in Task 2, grows each task):** `tests/test_translations.py` solves every problem in the problem bank, `web/solve-examples.json` and `web/textbook-problems.json` through `handle(..., lang)` for each language and asserts no user-facing text field (`text`, `title`, `summary`, `answer_text`, `kind_label`, `label`, `message`, `hints`, `rule`, `example`, `mistake`, `error`) is left as English — a field is English when it is not a `Message`, or its template's translation is null. Families not yet wrapped are listed in an `xfail` set that shrinks to empty by Task 6.
